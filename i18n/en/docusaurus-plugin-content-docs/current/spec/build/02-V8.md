# Official static V8 integration

## 1. Source and version

Use unmodified official V8 **13.6.233.17**, commit `b0a55a7dad7f536cce1f9aaddba89894c8533946`, locked by ZenTS~/v8/official-source-lock.json. ZenTS does not use Puerts SDK releases, binding layers, or runtime, and does not embed Node.js. Adapters build separately without patching upstream V8.

Build V8 as static libraries, then link adapters. Do not embed the V8 source tree in IL2CPP or rebuild V8 on every Unity compile.

## 2. Artifacts

| Platform | Integration |
|---|---|
| Windows Editor/Win64 | Static V8 inside DLL / Player libraries |
| macOS Editor/Player | Static V8 inside dylib / arm64/x64 libraries |
| Android | Target-ABI static libraries built with Linux/NDK |
| iOS/simulator | Separate JITless libraries exported to Xcode |
| WebGL/WeChat | HostJs, no linked V8 |

OS/CPU, device/simulator, compiler, and GN configurations are not interchangeable. Unsupported native targets have no fallback.

## 3. Build and install

Windows uses build_official.py then build_win64.py; Apple/Android use build_platform.py. Build outside the package and import complete SDKs with import_platform.py or the Editor menu. See [installation commands](../../guides/install.md).

Identity covers revision, target, toolchain, GN, JITless, ICU/snapshot options, adapter sources, and SHA-256 files. Header macros must match linked libraries. Do not edit manifests to bypass mismatches. Adapter rebuilds can reuse unchanged matching original V8 libraries.

SDKs install into Library; Editor binaries/stable metadata generate into Assets. Do not write packages or overwrite loaded plugins; restart to activate updates. Distribute validated complete SDKs rather than committing generated binaries.

## 4. Execution boundary

V8Engine.cpp implements EngineApi; V8Mono.cpp is the Editor ABI, with managed P/Invoke in Runtime/Mono/Engine/V8. CLR plans do not contain V8 handles/locals or raw moving-object addresses. See [ownership](07-ENGINE-BOUNDARY.md). Inspector is Editor-only.

## 5. Validation

Windows Editor/Win64 and macOS arm64 Editor have latest 435-case results. macOS Players, Android emulators, and iOS x64 Simulator have runtime validation; iOS arm64 compilation is unsigned only. macOS x64 Editor plugin is compile-only. See [status](../03-ALIGNMENT.md); a build-script option is not physical-device evidence.
